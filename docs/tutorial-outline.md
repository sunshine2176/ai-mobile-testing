## 0. 定位与红线

- **一句话卖点**：不写一行 XPath，让 AI 在真机上替你跑移动端测试——零 API key、零视觉模型、零额外服务，一台安卓手机 + 一根数据线就能跟做。
- **红线**：不出现公司平台/内部工具名（主业内容连脱敏都不做）；OCR/YOLO 只在「进阶」一节点名存在，不进正文链路。
- **读者画像**：会装 Node 和 adb 的测试/开发人员；手边有一台开了 USB 调试的安卓真机（或模拟器）。
- **差异化**：不是「裸调 MCP 工具」的玩法文，是「分阶段方法论 + 生成可回归的 TestNG 代码」的工程文。
- **目标读者收益**：跑通「一句话 → 真机执行 → 生成 TestNG 代码」全流程；带走的可复用资产 = 一套专家 SOP + 一份踩坑记录。

## 1. 教程正片结构（六节 + FAQ）

### §1 为什么是 Appium MCP（钩子，~600 字）
- 痛点：传统移动端自动化的三高——门槛高（Java/Python + Appium 全家桶）、维护高（XPath 一改就碎）、复现难。
- 转折：MCP 时代，"浏览器插件 + 自然语言"取代"IDE + 脚本语言"。
- 本教程覆盖范围声明：Android 真机 + 系统设置 App（零 APK 分发问题，读者拿自己手机就能跟）；iOS 留到续篇。
- **素材采集**：无（纯观点）。引用 appium-mcp GitHub star 数（写时查）。

### §2 15 分钟环境准备（实操，记录每一步的坑）
- 清单：Node ≥22 / JDK / Android SDK（adb）/ 一台真机（USB 调试开启）
- WorkBuddy 侧：写 MCP 配置（ANDROID_HOME 显式写死路径）→ Trust → 工具列表出现
- **素材采集**：每步实际耗时；`adb devices` 截图；MCP 配置 JSON 截图；Trust 按钮位置截图；首次 `npx appium-mcp@latest` 冷启动耗时（数字！）
- **预埋坑位**：ANDROID_HOME 未设 → 工具调用报错的具体表现；Node 版本卡线 v22 要求。

### §3 第一条指令：打开设置关蓝牙（全流程首跑）
- 场景：「打开设置，找到蓝牙开关，把它关掉」
- 流程：创建真机会话 → 截图 → 点击搜索/导航 → 断言蓝牙状态
- **叙事衔接（2026-10-27 实测后加）**：首跑**故意选顺利的场景**——正文结尾必须点破「这次为什么这么顺：路径明确，模型无需决策」，作为 §5 的铺垫钩子。读者跑完太顺 → 反而质疑 §5 立论，断层就在这里，务必接住。
- **素材采集**：自然语言指令原文；AI 实际调用的工具调用链（探索→定位→执行→断言）；每步工具返回的截断输出；首跑总耗时；真机屏幕录像（可选，后补）
- **预埋坑位**：华为/荣耀等定制 ROM 设置页结构差异；元素找不到时 AI 的重试行为观察。

### §5 分阶段方法论：不裸调工具（差异化核心，图 + 文）
- 名词定义（正片开头先讲清，避免读者困惑）：**裸调 = 把 40+ 工具一次性全交给 AI，不施加任何阶段约束，它自己决定工具选择与顺序。**
- 立论分三档（2026-10-27 实测后修订：首跑关蓝牙实测无阻碍，「裸调会乱」在路径明确型上已证伪）：
  - **确定的事 ①**：路径不明确的任务里，无约束试错烧轮次；跳过页面验证直接生成代码，定位策略可能基于想象的页面结构。
  - **确定的事 ②**：**SOP 是模型参差的对冲**——教程读者用的 AI 助手参差不齐（写作者用强模型实测顺利，不等于读者的模型也顺利）；SOP 把流程纪律从模型能力里解耦，让中等模型稳定产出。这条最扎实，放 C 位。
  - **待验证的假设**：案例 A（审计位置开关）上裸调的混乱程度——**实验照跑**。若证伪（模型强到案例 A 也顺），本节主立论退到「模型对冲 + 可复现性 + 生成前验证纪律」，证伪过程本身就是教程素材。
- 解法：专家 SOP 四阶段：**探索 → 设计 → 执行 → 固化**，每阶段有明确的工具子集 + 进出条件
- 配架构图（就是今天画的那张）+ SOP 表格
- **素材采集**：同一场景「裸调 vs SOP」的对比数据——工具调用轮次、耗时、成功与否（数字对比是杀手锏）；对比任务必须选**路径不明确型**，案例候选（2026-10-27 定）：
  - **A（首选）**：「找出设置里所有与位置信息相关的开关，记录每个当前开/关状态」——遍历+聚合+记忆三重负担，成功判定客观（对照 adb dump / 人工核对），且"审计"形态本身是企业付费场景，叙事顺。
  - B（备选）：列所有 App 通知权限现状——探索面最大，但核对工作量也大。
  - C（弃）：勿扰模式验证——验证方式不唯一，判定主观，不选。
- **预埋坑位**：AI 跳过探索直接点（如何用 prompt 约束）。

### §5.5 进阶一瞥（钩子，~300 字）
- 一句话点到：生产环境可加视觉定位（appium-mcp 的 `appium_ai`，需自配外部视觉 API key，默认不开启）+ OCR/YOLO 自建服务（本文不展开）
- 顺手埋续篇钩子：iOS 真机（WDA 签名）、CI 集成、模拟器 farm
- **素材采集**：无。可引用官方文档链接。

### §6 价值观与推广（收尾，~400 字）
- 回扣开头：这不是玩具，是「自然语言→真机→代码资产」的完整闭环
- 一人公司/服务视角：这套能力可直接变成测试自动化服务能力（脱敏案例形态）
- 互动引导：评论/issue 留言，收集"你最想让 AI 自动化的手机操作"
